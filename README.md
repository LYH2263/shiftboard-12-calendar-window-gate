# 06-shiftboard（交班台）

交班台 — 班次责任与在途批次交接：班次登记 → 在途批次归属 → 交班互斥办理 → 交班前后对账。

**不是** 多源 Feed 归并，**不是** 作业依赖编排，**不是** CDC 变更流，**不是** 质检签发，**不是** 数仓贴源/明细/汇总分层。  
**也不是** OA 考勤排班后台、电商订单、报表 CSV 看板。

## 启动

本地开发：

```bash
# 后端
cd backend
pip install -r requirements.txt
set DATA_DIR=%CD%\data
set FIXTURES_DIR=%CD%\..\fixtures
uvicorn app.main:app --host 127.0.0.1 --port 10600

# 前端
cd frontend
npm install
npm run dev
```

## 主链

登记班次与值班人 → 在途批次归属当前班次 → 发起交班（全仓同时仅一单进行中）→ 完成交班整批过户 → 交班对账报告与清单/批次同源

## 交班日历窗

### 配置

- 班次页可为每个班次配置多段交班日历窗：**星期几（1=周一 … 7=周日）+ 本地墙钟起止时刻 HH:MM**。
- 结束时刻允许 `24:00`；结束早于起始视为跨午夜（如 `22:00–06:00` 表示该星期 22:00 到次日 06:00）。
- 未配置任何窗口 = 该班次**禁止**交班（不是“全天可办”）。种子数据默认每天 `00:00–24:00`。
- 接口：`GET /api/shifts`、`PUT /api/shifts/{id}/windows`；裁决预览：`GET /api/handovers/window-status?from_shift_id=&to_shift_id=`。

### 裁决规则

- 发起与完成都必须落在 **交班方日历窗 ∩ 接班方日历窗** 内；任何一侧出窗都拒绝，不存在只查交班方的捷径。
- 裁决使用本地墙钟时刻。出窗时返回拒绝原因（哪一方、哪段窗、裁决时刻、最近可办交集时段）。

### 完成裁决的固化（快照表形态）

选择**独立窗快照表** `handover_window_snapshots`（另一种“写入交班单不可变列”的形态未采用）：

- 发起、完成各写一条快照：交班单 id、阶段（发起/完成）、裁决时刻、双方班次 id、双方窗定义 JSON、两侧是否在窗、交集是否成立、拒绝原因。
- `(handover_id, phase)` 唯一；表上建有 `BEFORE UPDATE/DELETE` 触发器直接 `RAISE(ABORT)`，快照只增不改。
- 因此**事后改窗不会把历史完成单改判**：完成裁决永远读快照，不回查当前配置。

### 出窗失败闭（同一事务检测出窗 + 回滚）

在 `BEGIN IMMEDIATE` 事务内完成“重读双方当时配置 → 按完成时刻墙钟裁决”：

- 出窗：单据标 `失败`（原因可读、可重新发起），**不过户**，班次状态复位，对账报告记录“未发生过户”。
- 一致性校验失败：过户写入包在 `SAVEPOINT` 中，`ROLLBACK TO` 后落失败单，零半截过户。
- 任何异常抛出都会整体 `ROLLBACK`，不存在“批次已过户一半、单据才判失败”的中间状态。

> 说明：本应用时间源为进程本地时间（`services/handover.py: now_local`），测试可注入固定时钟以覆盖跨午夜/出窗场景。
